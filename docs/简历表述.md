# 简历怎么写（可直接改名字用）

## 项目标题

端侧 LLM 策略执行引擎（自然语言 → 结构化设备动作）

## 一句话

在 Orange Pi 5（RK3588S / 8GB）部署 Qwen2.5-0.5B（W8A8 / RKLLM），将自然语言转为经策略/规则层与 Schema 校验的设备动作；安全拒答微秒级，合法控制约 1.3s，混合方案评测 30/30，相对纯 LLM 提升 53.3 个百分点。

## 子弹点（建议 4 条）

1. 完成 RKLLM 1.2.1 端侧部署与版本对齐，解决板载 runtime 1.0.1 与模型不兼容；给出 0.5B/1.5B 的 TTFT、tok/s、RSS 对照（0.5B：82ms / 26tok/s / 640MiB）。
2. 设计「策略规则层 + LLM + Schema + 高危确认 + 审计」执行引擎：越权/注入硬拒，合法软控制走模型，输出可验证可回放。
3. 自建 30 条评测集并做消融：纯 LLM 正确率 46.7%，混合方案 **100%**（+53.3pt）；安全拒答 P50 从 ~2.5s 降到 **0.04ms**。
4. 实现常驻推理进程与 HTTP 执行面（`/v1/control`），避免逐条冷加载；支持一键消融与演示脚本。

## 面试追问预案

- **策略层是不是把模型架空了？**  
  规则命中 60%，管安全边界；合法调参/禁区等仍走 LLM（合法路径 ~1.3s 可证明）。
- **为什么 0.5B？**  
  8GB 内存与交互延迟；1.5B 作对照（更慢、更吃内存）。
- **和本地知识库聊天有何不同？**  
  输出是动作契约，失败可拒答，有确认与审计，不是开放生成。
- **如何防越权？**  
  入口策略 + Schema 白名单 + deny 子串 + 高危确认，模型不可直接执行。
